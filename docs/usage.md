# AgentHighlight 사용 안내

Claude Code·Codex 같은 에이전트와 문서나 Figma 를 같이 보며 이야기할 때, 에이전트가 "응답 필드 표의
세 번째 행" 이라고 말하면 그 자리를 화면에서 다시 찾아야 한다. AgentHighlight 를 깔아 두면 에이전트가
그 자리를 화면 위에 직접 표시한다. 바깥이 어두워지고 대상만 밝게 남아 빨간 테두리와 라벨이 붙는다.

표시가 떠 있어도 클릭과 스크롤은 평소대로 된다. 하던 작업을 멈출 필요가 없다.

## 설치

macOS 에서 저장소를 받아 한 번 실행한다.

```bash
make install
```

설치가 하는 일:

- 메뉴바 앱을 `~/Applications/AgentHighlight.app` 에 두고 띄운다.
- 셸 명령 `hl` 을 `/usr/local/bin`(쓰기 권한이 없으면 `~/.local/bin`)에 넣는다.
- Claude Code·Codex 등이 설치돼 있으면 에이전트용 스킬 `agent-highlight` 를 연결하고, 에이전트가
  `hl` 을 부를 때마다 승인을 묻지 않게 허용 목록에 올린다.

마지막에 `PATH 에 ... 이 없습니다` 가 나오면 안내대로 셸 설정에 경로를 추가한다.

### 접근성 권한 켜기

처음 띄우면 접근성 권한 창이 뜬다. 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용에서
AgentHighlight 를 켠다. 창을 닫았으면 메뉴바 아이콘의 "접근성 권한 열기..." 로 같은 화면에 간다.

권한이 없어도 화면 좌표와 창 전체는 표시된다. 문서 안의 문구를 찾아 가리키는 기능은 권한이 있어야
한다. 다시 빌드해 설치하면 권한이 풀리는 경우가 있으니, 표시가 안 되면 이 설정부터 본다.

설치가 끝났는지는 이렇게 확인한다.

```bash
hl doctor
```

`"appRunning": true` 와 `"trusted": true` 가 보이면 준비가 끝난 것이다.

## 에이전트에게 부탁하기

스킬이 연결돼 있으면 에이전트가 알아서 `hl` 을 부른다. 설명이 화면의 특정 위치를 가리키는 순간
표시가 뜬다. 직접 부탁해도 된다.

- "Chrome 에 열린 ADR 에서 응답 필드 표를 가리켜 줘"
- "이 Figma 링크 열어서 가입 버튼 보여줘"
- "요청이 어디서 시작해 어디로 가는지 화면에서 순서대로 짚어 줘"
- "PR 123 을 커밋 순서대로 안내해 줘"

에이전트는 답변 본문에도 같은 번호로 설명을 적는다. 화면의 (1)(2) 배지와 답변의 (1)(2) 를 맞춰 읽으면
된다.

## 화면에서 보는 것과 조작

### 한 번에 뜨는 표시

대상 하나 또는 여러 곳이 한꺼번에 뜬다. 여러 곳이면 1부터 번호 배지가 붙는다. 8초쯤 지나면 저절로
사라진다(에이전트가 시간을 늘릴 수 있다).

- 바로 지우려면 Esc 를 누른다. 이 Esc 는 지우는 데만 쓰이고 앞에 있는 앱에는 전달되지 않는다.
- 메뉴바 아이콘의 "하이라이트 지우기" 로도 지운다.
- 대상이 화면 밖에 있으면 그 위치까지 스크롤한 뒤 표시한다.

### 단계별 안내

순서가 있는 설명은 한 곳씩 넘기며 보여준다. 화면 한쪽에 카드가 뜨고 `2 / 5` 같은 진행 번호, 지금
단계 제목, 여기서 볼 것, 다음 단계 제목이 적혀 있다.

| 키 | 동작 |
|---|---|
| 오른쪽 화살표 | 다음 단계. 마지막 단계에서 누르면 끝난다 |
| 왼쪽 화살표 | 이전 단계 |
| Esc | 안내 전체를 끝낸다 |

화살표는 안내 중인 앱이 맨 앞에 있을 때만 가로챈다. 터미널로 돌아와 에이전트에게 질문을 입력할 때는
화살표가 평소대로 동작한다. 단계를 넘길 때마다 대상을 다시 찾아 스크롤하므로, 중간에 직접 스크롤해도
다음 단계 위치는 어긋나지 않는다.

탭을 바꾸는 등으로 그 단계의 대상을 못 찾으면 화면 가운데에 그 사실이 적힌 카드가 뜬다. 오른쪽
화살표로 그냥 넘어가면 된다.

### PR 안내

GitHub PR 화면은 스크롤해야 아래쪽 줄을 그리기 때문에 문구를 찾지 못한다. 그래서 PR 안내를 부탁하면
에이전트가 diff 를 로컬 페이지로 만들어 새 Chrome 창(`PR <번호> guide ...`)으로 연다. 커밋마다 한
섹션이고, 그 위에서 단계별 안내가 진행된다. 이 창은 다 보고 나서 닫으면 된다.

## 직접 써 보기

에이전트 없이 터미널에서 바로 불러도 된다. 결과는 JSON 으로 나온다.

```bash
# Chrome 창에서 문구를 찾아 가리킨다
hl text "응답 필드" --app "Google Chrome" --title "ADR" --label "여기"

# Figma 링크를 열고 노드를 보여준다
hl figma "https://www.figma.com/design/<파일>?node-id=1-2" --label "가입 버튼"

# 창 전체, 화면 좌표
hl window --app "Google Chrome" --title "JIRA"
hl rect 200 200 400 120 --label "이 영역"

# 지금 열린 창 목록과 좌표
hl windows --app chrome

# 지우기
hl clear
```

자주 쓰는 옵션:

| 옵션 | 뜻 |
|---|---|
| `--duration <초>` | 표시 시간. 기본 8, 0 이면 지울 때까지 남는다 |
| `--no-activate` | 대상 앱을 앞으로 올리지 않는다 |
| `--no-dim` | 바깥을 어둡게 덮지 않는다. 기본값은 메뉴바의 "바깥 어둡게" 를 따르고 처음엔 꺼져 있다 |
| `--color #RRGGBB` | 테두리 색 |
| `--index <n>` | 같은 문구가 여러 번 나올 때 n 번째(0부터) |

전체 명령은 `hl help` 로 본다. 여러 곳 표시(`hl json`)와 단계별 안내(`hl steps`)에 넣는 JSON 형식은
[에이전트용 안내](../skills/agent-highlight/SKILL.md)에 있다.

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 아무것도 안 뜬다 | `hl doctor` 에서 `appRunning` 이 false 면 앱이 꺼진 것이다. `hl` 이 다시 띄우지 못하면 `make install` 을 다시 돌린다 |
| 창이나 좌표는 되는데 문구는 못 찾는다 | `trusted` 가 false 다. 접근성 권한을 다시 켠다 |
| 문구를 못 찾는다(`no element matching`) | 문구를 더 짧게 잡는다. 표 제목이나 헤딩처럼 한 덩어리로 된 글이 잘 잡힌다 |
| 탭을 바꿨더니 표시가 엉뚱한 곳에 남았다 | 표시는 그린 자리에 그대로 남는다. Esc 로 지운다 |
| Figma 가 다른 브라우저나 Figma 앱에서 열렸다 | `hl figma` 는 기본으로 Chrome 창을 찾는다. `--app` 으로 그 앱을 지정한다 |

## 알아 둘 한계

- Figma 캔버스 안의 레이어 위치는 잡지 못한다. node-id 링크로 Figma 가 노드를 선택·확대하게 하고 창
  위에 라벨을 띄운다. 더 좁은 영역을 보려면 하위 노드의 링크를 쓴다.
- GitHub 코드 뷰(`/blob/...`)와 PR diff 화면 안의 문구는 못 찾는다. PR 은 위의 PR 안내로 본다.
- Orca 내장 브라우저 안의 페이지는 문구 단위로 가리키지 못한다. 창과 좌표는 된다.
- 표시는 macOS 에서만 된다.
